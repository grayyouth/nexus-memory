# 🤖 Инструкция для агентов (Cline / Gea / локальные LLM)

> **Прочитай эту инструкцию в начале каждой сессии, где используется Nexus.**
> Она объясняет, как подключаться к Nexus и как вести себя как «сопроцессор».

---

## 1. Что такое Nexus

**Nexus** — общая память агентов. Хранит знания, сессии и совместные решения
в файлах на диске (`nexus_store/`). Ты к нему подключаешься через **MCP**.

**Принцип «сопроцессора»:**
- Человек принимает решения, ты (агент) — генерируешь и исполняешь.
- Ничего важного **не держи в голове** между сессиями — Nexus забудет вместе с тобой.
- Всё, что ценно: **запиши в Nexus**.

**Твоё правило:** если это оказалось полезным / сложным / повторяющимся —
сохрани в Nexus, чтобы следующая сессия (твоя или ИИ-коллеги) не начиналась с нуля.

---

## 2. Как подключиться (MCP)

Сервер Nexus уже настроен в конфиге:

```json
{
  "mcpServers": {
    "nexus": {
      "command": "python",
      "args": ["путь/к/репо/nexus_mcp_server.py"],
      "env": {}
    }
  }
}
```

> Замените `путь/к/репо` на реальный путь к клонированному репозиторию.

- **Путь к серверу:** `nexus_mcp_server.py` (в корне репозитория)
- **Тип транспорта:** stdio (MCP по стандартному вводу/выводу)
- **Проверка:** в новой сессии сразу вызови `get_context(agent_id=...)` — если ответ не «ошибка», ты подключён.

После подключения тебе доступны инструменты (Tools):

| Инструмент | Что делает |
| :--- | :--- |
| `get_context(agent_id, project_id?)` | Загрузить «память» перед началом работы (сводку прошлых сессий, решения проекта + дайджест изменений). |
| `project_digest(project_id, since?, exclude_agent?, agent_filter?)` | Кросс-агентный дайджест проекта: сессии ВСЕХ агентов + совместные решения + свежие заметки. `since=<время твоей последней сессии>` → «что изменилось, пока меня не было». |
| `add_note(content, tags, project_id?, source?, agent_id?)` | Сохранить знание/факт/вывод в библиотеку. |
| `search_knowledge(query, tags?, project_id?, agent_id?)` | Найти информацию в базе. |
| `archive_current_session(agent_id, session_data)` | Сохранить сырой лог текущей сессии. |
| `record_joint_decision(project_id, decision, by_agents, reason)` | Записать совместное решение нескольких агентов. |
| `generate_session_summary(agent_id, session_id?)` | Автосводка архивной сессии (Сделано/Решения/Дальше), без LLM. |
| `collapse_session_history(agent_id, keep_last=1)` | Свернуть старые архивы в одно резюме истории. |
| `end_session(agent_id, session_data, collapse_after?, keep_last=1)` | Завершить сессию одним вызовом: архив + автосводка (+ опционально collapse). |
| `semantic_search(query, ...)` | Поиск по смыслу (векторы + ключевое совпадение), RU/EN. |
| `build_context_prompt(query, ...)` | Готовый компактный блок контекста под задачу (бюджет символов). |
| `run_ingestion(max_files?)` | Запустить обработку `input_docs/raw/` → чанки в библиотеку (включая OCR изображений). |
| `get_ingestion_status()` | Посмотреть лог обработки документов. |
| `start_watchkeeper(interval=300)` | Запустить авто-ingestion: сканирует `raw/` каждые N секунд. |
| `stop_watchkeeper()` | Остановить авто-ingestion. |
| `watch_status()` | Статус watchkeeper: сканы, файлы, ошибки. |
| `ocr_scan_images(directory, engine?, languages?)` | Сканировать директорию изображений и извлечь текст через OCR. |
| `ocr_extract_image(image_path, engine?, languages?)` | Извлечь текст из одного изображения. |
| `ocr_status()` | Доступные OCR-движки и форматы. |
| `config_get()` | Показать текущие настройки. |
| `config_set(section, key, value)` | Обновить одно значение в конфиге. |
| `config_update(settings)` | Обновить несколько значений за раз. |
| `web_fetch(url, extract_content?, timeout?)` | Скачать веб-страницу и вернуть контент. |
| `web_save(url, project_id?, timeout?)` | Скачать и сохранить веб-страницу в `raw/` для индексации. |
| `web_status()` | Доступные способы скачивания (requests / urllib). |
| `orch_start_task(task_id, agent_id, project_id, description?, model?, variant?)` | Запустить задачу в оркестраторе. |
| `orch_end_task(task_id, agent_id, session_data?)` | Завершить задачу и сохранить сессию. |
| `orch_status()` | Статус оркестратора: задачи, агенты, проекты. |
| `orch_list_tasks(agent_id?, project_id?, status?)` | Список задач с фильтрами. |

Для локальных LLM с малым контекстом: `build_context_prompt("<задача>")`
вернёт готовый компактный блок контекста — вставляй его в промпт вместо
«прочитай все файлы». `semantic_search` ищет по смыслу, когда ключевой поиск
молчит (перефразировки). Ограничение zero-dep эмбеддера: нет RU↔EN кросс-языка —
ищи на языке заметок или поставь `pip install sentence-transformers`
(модуль подхватит нейро-эмбеддинги автоматически).

> Если MCP-сервер уже подключён к среде — просто используй эти инструменты.
> Если нет — скажи пользователю, что нужен конфиг из `nexus_mcp_config.json`.

## 3. Обязательный ритуал сессии

### А. В начале сессии — «загрузиться»

Вызови `get_context(agent_id="cline", project_id="<если знаешь проект>")`.

Это даст:
- сводку твоей последней сессии,
- совместные решения по проектам.

Если в ответе нет ничего или «No prior context found» — значит это новая стезя, начинай с чистого листа, но **записывай всё важное** дальше.

### Б. Во время работы — «пиши в память»

Делай это:
- **после каждого крупного результата** (решение, найденная причина бага, изученный подводный камень);
- **когда нашёл что-то в интернете** — сохраняй через `add_note` с `source=<URL>`;
- **когда принято решение с другим агентом** — через `record_joint_decision`.

Формат `add_note`:
```
add_note(
  content="<что узнал/решил, кратко и точно>",
  tags=["#архитектура", "#решение", "#проект:<имя>"],
  project_id="<имя проекта>",
  source="<откуда данные, опционально>",
  agent_id="cline"
)
```

### В. В конце сессии — «сохранить всё одним вызовом»

1. **Один вызов `end_session` (предпочтительный способ):**

```
end_session(
  agent_id="cline",
  project_id="<имя проекта>",           // обязательно, чтобы сессия попала в дайджест проекта
  session_data={"actions": [...], "decisions": [...], "next_steps": [...],
                "chat_history": [...]}, // ключи можно по-русски: сделано/решения/дальше
  collapse_after=false,  // true — заодно свернуть старые архивы (keep_last=1)
)
```

Инструмент сам: архивирует сырой лог → генерирует автосводку
(*Сделано / Решения / Дальше*) → (опционально) сворачивает историю.
Сводка автоматически попадёт в `get_context` следующей сессии.

**Чтобы другие агенты видели твою работу по проекту** — всегда передавай
`project_id`, а в начале следующей сессии вызывай
`project_digest(project_id, since=<твоя последняя сессия>)`.

2. **Ручная альтернатива** (если нужен контроль по шагам):
   `archive_current_session(agent_id="cline", session_data={...})` →
   `generate_session_summary(agent_id="cline")`. Ручной способ через ядро
   (`store_session_summary`) остаётся как запасной вариант.

Структурируй `session_data` понятными ключами — тогда автосводка получится точной.

Обязательно выводи итог сессии **в 3 пунктах максимум**: *Сделано / Решения / Дальше*.

## 4. Твой режим работы с Nexus

Помни философию проекта: **Nexus — это процессор, а не замена мышления**.

| Ты (агент) | Nexus |
| :--- | :--- |
| Анализируешь, планируешь, генерируешь | Хранит, ищет, индексирует |
| Принимаешь решения по задаче | Запоминает решения между сессиями |
| Читаешь и проверяешь | Отдаёт нужные куски контекста |
| **Отвечаешь за результат** | Систематизирует хаос в структуру |

**Не создавай хаос в библиотеке:** добавляй заметки только если они помогут
будущей сессии. Мусор в памяти — это мусор в контексте всех агентов.

## 5. Когда вызывать `run_ingestion`

- Если в проекте появились файлы в `nexus_store/input_docs/raw/`.
- Если пользователь просил «сохрани эту статью/доку в память».
- Раз в несколько сессий — для поддержания библиотеки в актуальном состоянии.

## 5.1 Watchkeeper (авто-ingestion)

Вместо ручного запуска `run_ingestion` можно включить Watchkeeper — он будет
автоматически сканировать `raw/` каждые N секунд и обрабатывать новые файлы:

```
start_watchkeeper(interval=300)   // 300 сек = 5 минут
watch_status()                     // проверить статус
stop_watchkeeper()                 // остановить при необходимости
```

Или из CLI:
```bash
python nexus_cli.py watch --interval 300   # запустить
python nexus_cli.py watch --status         # показать статус
```

**Когда использовать:**
- Пользователь положил файлы в `raw/` и хочет, чтобы они попали в библиотеку.
- Долгосрочный мониторинг: Watchkeeper работает в фоне и не требует внимания.
- Не нужен для разовых операций — в этом случае `run_ingestion` быстрее.
